## Overview

The web client is a dependency-light React 18 single-page interface for configuring and playing local Qwixx matches. The core game engine is a pure state machine; the UI owns setup data, the current `GameState`, activity history, and AI turn scheduling.

## Components

| Component | Location | Purpose |
| --- | --- | --- |
| `App` | `src/ui/App.tsx` | Switches between setup and active game state |
| `SetupScreen` | `src/ui/App.tsx` | Configures players, board preset, and an optional deterministic seed |
| `GameScreen` | `src/ui/App.tsx` | Coordinates legal actions, AI turns, feedback, and match layout |
| `DicePanel` / `Die` | `src/ui/App.tsx` | Displays active dice and white-dice total |
| `PlayerCard` | `src/ui/App.tsx` | Renders a player's score sheet and legal mark targets |
| Stylesheet | `src/ui/styles.css` | Global visual system and responsive layout |

## Dependencies

- React 18 hooks for local UI state and effects.
- `src/core/engine.ts` for legal actions and immutable state transitions.
- `src/core/scoring.ts` for live score summaries.
- `src/ai/bots.ts` for delayed local AI decisions.

## Data Flow

`Setup` → resolve an explicit or per-match random seed → board/rules configuration → `newGame()` → `GameState` → `legalActions()` → user or bot action → `applyAction()` → updated `GameState`. The resolved seed lives in `GameState.config` and drives dice, randomized boards, and per-player AI randomness. UI history is derived at transition time and intentionally stays outside the serializable engine state.

## Key Patterns

- All gameplay mutations go through the core engine; UI changes must not duplicate game rules.
- Legal score cells are projected into a keyed `Map`, which drives button enablement.
- AI turns use a short timeout and deterministic per-player random generators.
- The app has no component library, router, icon package, or external state dependency.

## Integration Points

- `GameState.phase`, `currentActor`, and `legalActions` drive action guidance and affordances.
- Board presets expose human-readable names and special-rule metadata for setup descriptions.
- `computeScore` supplies live and final standings without mutating game state.

## UX Risks Identified

- Setup choices have little explanatory context and weak visual grouping.
- The current action, stage progression, and legal target count are not sufficiently prominent.
- Exiting an active match is destructive and currently has no confirmation.
- Long score rows can become cramped or overflow on narrow screens.
- Focus, live announcements, empty states, and reduced-motion behavior need explicit treatment.
